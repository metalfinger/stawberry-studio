# Story to storyboard, in any local assistant host

## Start or resume

Discover tool schemas. List projects and resolve the user's intended production.
For existing work, read project, workflow, pending jobs and relevant original
sources before creating anything. A generated output and a submitted job are
different states. Recover a known job before considering another submission.
The engine and media directory must travel together when switching computers;
use the existing export/import or backup commands. On the same computer use the
same absolute store directory across hosts.

## Develop the whole production

Capture the original story and references. Persist delegated choices as assistant
proposals, distinct from user facts. Resolve only material missing information.
Create the full scene/shot/cut structure using the creative playbooks. Record
each beat's purpose, duration, framing, action, emotional change and transition.
Check total duration, redundant coverage, reveal timing and breathing room.
Preserve editorial order separately from story chronology.

Derive characters, locations, sublocations, wardrobe states and props across all
cuts. Reconcile aliases. Link actual visible subjects per cut; an available
character need not appear. Plan useful views based on those cuts. Character and
prop sheets normally use neutral backgrounds; location references describe
connected geography and landmarks. Avoid inventing extra views for every asset.

## Prepare each image intelligently

Read resolved `context`, not only local node fields. Review the cut's action,
camera, composition, lighting, state transitions, notes and relevant siblings.
Choose references from the full library, including non-adjacent cuts. Explain
the optional base choice; never automatically use the last generated image.

Write a numbered reference map into the final prompt itself: image 1 supplies
which identity/geography/composition, what to retain, what to change and what
must not transfer. This map must match recipe reference order exactly. The
provider cannot see database-only role instructions. Use one decisive still
moment per frame even when the shot describes motion across time.

Retrieve the actual model contract. Preserve required references within its
limits; if necessary propose a derived sheet with provenance. Do not silently
drop references. Freeze the final prompt/settings/ordered inputs using prepare.

## Execution and continuation

Record the user's authorization at the scope they actually granted. Routine
storage and progress operations need no additional confirmations. An autonomous
request can authorize continued execution, but it does not establish observed
anatomy, likeness or prop coverage.

For each recipe: approve under the recorded scope, enqueue, submit through the
available provider connector, and retain the returned provider job ID at once.
Use external_preview and attach_external for exact receipt reconciliation.
The existing worker collects outputs locally. Inspect job state; a download
retry must not regenerate an image. Never parse an arbitrary UUID out of prose
when the connector returns structured job records.

Review/selection currently use the strict existing engine contract. Do not
fabricate depicted-assets confirmations from a prompt to pass that gate. Until
an explicit unverified-continuation state is implemented, explain this limitation
when an unattended production needs an unreviewed output as its next reference.
The historical dream-run helper does not provide a general solution to this.

## Evaluation and refinement

Respect the user's chosen review mode. Future automated checks should record
their evaluator, evidence, confidence, and specific discrepancies separately
from human review. Check anatomy, identity, required objects, location landmarks,
screen direction and story state. Rhythm needs a sequence-level review as well
as individual-frame checks. Automatic repairs require a bounded retry and credit
policy; those enforcement features are not implemented yet.

## Finish

Verify complete chronology, local outputs, exact recipes and receipts, and open
issues. Export the project with media and an agent-readable story manifest.
Keep original transcript, adaptations and observed results distinguishable.
Report technical completion separately from visual quality. Leave the viewer
available and provide its actual URL.
